# Proposal

## Why

当前工具只能一次性完成打点后导出 SRT，打到一半关掉就会丢失全部时间，无法第二天继续。清空某行错误时间需要分别清空两个输入框；预览在歌曲开头尚未进入任何时间戳时不会主动定位歌词；应用仍使用通用的 “SRT Tool” 名称。把应用命名为 Euterpe（希腊诗歌与音乐女神），并补上工程文件与几处编辑体验，可以让它更像一个可持续使用的歌词打轴工作台。

## What Changes

- **BREAKING**：可执行文件、安装包显示名、窗口标题与界面标题统一改为 **Euterpe**（Windows 下可执行文件为 `Euterpe.exe`）。
- 新增 `.eusrt` 工程文件：以带版本号的 JSON 保存歌词行、开始/结束时间、音频路径与音频显示名，支持再次打开继续编辑。
- 新增“保存工程”与“打开工程”能力：首次保存选择路径，之后保存覆盖当前 `.eusrt`；打开工程会替换当前会话，未保存修改时先确认。
- 工程记录音频路径；打开时若音频文件已被移动或删除，仍恢复歌词与时间并提示，之后重新导入音频**不得清空**已恢复的时间。
- 工程文件名显示在界面左上角，存在未保存到工程的修改时追加 `*`；移除顶部“有未导出更改 / 已导出”徽标，保存或导出 SRT 不再以徽标形式提示。
- 编辑模式下点击歌词行后按 **R**，清空该行开始与结束时间；该操作进入历史，按 **O** 可回滚。
- 预览模式下，当播放位置早于所有已完成时间戳时，将歌词列表第一行滚动到可视区域中央；只居中，不高亮。
- 更新快捷键提示文案，加入 R 键说明。

## Capabilities

### New Capabilities

- `project-file`: `.eusrt` 工程文件的保存、打开、校验、音频路径恢复、缺失音频降级，以及左上角工程名与未保存 `*` 标记。
- `app-identity`: Euterpe 的可执行文件、安装包、窗口标题与界面标题命名。

### Modified Capabilities

- `lyric-timing`: 新增 R 键清空当前行时间戳，并纳入 O 键回滚历史。
- `lyric-scrolling`: 新增预览位置早于全部时间戳时居中歌词第一行的滚动规则。
- `media-import`: 替换前的确认从“未导出”改为“未保存到工程”，并允许已保存工程直接替换。
- `srt-export`: 导出成功不再清除工程未保存标记，也不再绕开未保存确认。

## Impact

- 打包配置：`src-tauri/tauri.conf.json` 的 `productName`、`mainBinaryName`、窗口标题；安装包与可执行文件名称随配置变化。
- 前端状态：`SessionState` 增加工程路径与工程保存版本；新增加载工程、保存工程、清空当前行时间、附加音频等 action；未保存判断改为工程维度。
- 键盘与 UI：`useKeyboardShortcuts` 增加 R；`App` 增加清空与工程保存/打开流程；`ExportBar` 增加“保存工程”；顶部徽标改为工程名 + `*`；快捷键提示更新。
- 文件 I/O：`ipc/files.ts` 增加 `.eusrt` 保存对话框与打开过滤器；复用现有 `read_file_bytes` / `write_text_atomic`；新增工程序列化/解析纯函数与校验。
- 预览：新增“首行居中”派生逻辑，继续复用 `useCenterOnActive`，不改变高亮判定。
- 测试：工程序列化/解析、状态机、快捷键、App 工程流程、预览定位、导出栏按钮。
- 不涉及网络、数据库或云同步；`.eusrt` 不内嵌音频，工程文件体积保持很小。
