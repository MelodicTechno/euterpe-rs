# project-file Specification

## Purpose

让用户把尚未完成的歌词打点会话保存为可再次打开的 `.eusrt` 工程文件，并在工程名旁清楚标识尚未保存的修改。

## Requirements

### Requirement: 保存工程为 .eusrt

用户 SHALL 能把当前会话保存为扩展名为 `.eusrt` 的工程文件。工程 MUST 包含格式标识、版本号、歌词文本及各行的开始/结束时间、音频路径与音频显示名。首次保存 MUST 让用户选择路径；已有工程路径时再次保存 MUST 覆盖该文件。

#### Scenario: 首次保存工程

- **WHEN** 用户对含音频与歌词的会话点击保存工程，并在对话框中选择位置
- **THEN** 应用写出 `.eusrt` 文件，内容包括当前歌词顺序、各行时间与音频路径

#### Scenario: 再次保存覆盖原工程

- **WHEN** 当前会话已有 `.eusrt` 路径，用户再次保存工程
- **THEN** 应用直接覆盖该路径，不再次弹出保存对话框

#### Scenario: 保存失败

- **WHEN** 写入 `.eusrt` 失败
- **THEN** 原有工程文件保持原样，应用提示保存失败

### Requirement: 打开工程并恢复会话

用户 SHALL 能通过导入入口或拖拽打开 `.eusrt` 工程。工程有效时，应用 MUST 替换当前会话，恢复歌词顺序、各行开始/结束时间、当前行，并在音频路径可读时恢复该音频。

#### Scenario: 打开有效工程

- **WHEN** 用户选择一个有效的 `.eusrt` 工程
- **THEN** 应用加载其中的歌词、时间与音频，并回到编辑模式继续打点

#### Scenario: 当前会话有未保存修改

- **WHEN** 当前工程的修改尚未保存，用户尝试打开另一个工程
- **THEN** 应用先要求确认替换，确认后才加载新工程

#### Scenario: 工程与其他文件同时导入

- **WHEN** 用户一次导入中同时包含 `.eusrt` 与音频或歌词文件
- **THEN** 应用拒绝导入，提示一次只能打开一个工程，并保持当前会话不变

### Requirement: 音频缺失时恢复歌词与时间

工程记录音频路径不可读时，应用 MUST 仍恢复工程中的歌词与时间并给出可见提示。用户随后导入音频时，应用 MUST NOT 清空这些已恢复的时间。

#### Scenario: 打开时音频不存在

- **WHEN** 工程中的音频路径已被移动或删除
- **THEN** 应用恢复歌词与时间，并提示音频缺失、可重新导入

#### Scenario: 缺失音频后重新导入

- **WHEN** 工程已恢复歌词与时间且当前没有音频，用户导入一个音频文件
- **THEN** 应用附加该音频并保留所有已恢复的歌词时间

### Requirement: 工程文件校验

应用 MUST 拒绝无法解析的 JSON、未知格式标识或不支持的版本。校验失败 MUST NOT 改变当前会话或覆盖任何工程文件。

#### Scenario: 打开损坏的工程

- **WHEN** 用户打开内容不是有效 JSON 或不含受支持格式标识的文件
- **THEN** 应用提示工程无效，当前歌词、时间与音频保持不变

#### Scenario: 打开不支持的版本

- **WHEN** 工程版本高于当前应用支持的版本
- **THEN** 应用拒绝打开并提示版本不受支持，当前会话保持不变

#### Scenario: 非法时间数据

- **WHEN** 工程中某行结束时间早于开始时间，或时间不是非负数
- **THEN** 应用判定工程无效并保持当前会话不变

### Requirement: 工程名与未保存标记

窗口标题 MUST 显示当前工程文件名；存在尚未保存到工程的修改时 MUST 在文件名后追加 `*`。保存工程或打开工程后 MUST 移除 `*`。导出 SRT MUST NOT 改变该标记。无工程但已有内容时显示 `未命名.eusrt`，修改后显示 `未命名.eusrt*`。界面 MUST NOT 再显示内嵌工程名或导出徽标。

#### Scenario: 新建会话出现未保存标记

- **WHEN** 用户导入文件并修改歌词时间，但尚未保存为工程
- **THEN** 窗口标题显示 `未命名.eusrt*`

#### Scenario: 保存后移除星号

- **WHEN** 用户保存工程成功
- **THEN** 窗口标题显示工程文件名且不带 `*`

#### Scenario: 保存后再次修改

- **WHEN** 已保存工程后用户又修改任一行时间或清空时间
- **THEN** 窗口标题中的工程文件名后重新出现 `*`

#### Scenario: 导出 SRT 不影响工程标记

- **WHEN** 工程存在未保存修改，用户导出 SRT
- **THEN** 窗口标题中的工程文件名和 `*` 保持原样，界面不出现内嵌工程名或导出徽标

### Requirement: 另存为工程

用户 SHALL 能通过 File > Save As 将当前会话保存到新的 `.eusrt` 路径。Save As MUST 始终打开保存对话框；成功后 MUST 更新当前工程路径，后续 Save 覆盖新路径，并移除窗口标题中的 `*`。用户取消时 MUST 保持当前工程路径与内容不变。

#### Scenario: 另存为新工程

- **WHEN** 用户选择 File > Save As 并选择新路径
- **THEN** 应用把当前会话写入新路径，并把新路径设为当前工程路径

#### Scenario: 取消另存为

- **WHEN** 用户在 Save As 对话框中选择取消
- **THEN** 当前工程路径、内容与窗口标题标记保持不变

#### Scenario: 另存为后再次保存

- **WHEN** 用户完成一次 Save As 后再次选择 File > Save
- **THEN** 应用直接覆盖 Save As 选择的新路径，不打开保存对话框
